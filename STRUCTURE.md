## Как устроен backend (слои)

Поток данных идёт сверху вниз, зависимости — только «вниз»:

```
handler (HTTP, gin)  →  service (бизнес-логика, RAM-кэши)  →  repository/gorm (БД)
        ↑                          ↑                                   ↑
     port (интерфейсы)      domain (чистые типы)              parser (разбор входных файлов)
```

- **domain** — чистые типы предметной области (вагон, план, справочники), без БД и HTTP.
- **port** — интерфейсы («что умеет хранилище/интеграция»), реализуются в `repository`.
- **service** — вся логика: конвейер обогащения дислокации, приём ЛК, матч плана; держит
  состояние в RAM-кэшах (БД читается на старте, пишется атомарной подменой снимка).
- **repository/gorm** — доступ к PostgreSQL (ORM-модель отделена от доменной).
- **parser** — разбор входных файлов (Excel ЛК, JSON АСУ, Excel план) в доменные типы.
- **handler** — тонкий HTTP-слой (gin), маппинг ошибок в коды; провод в `server.go`.

Точка сборки — `cmd/server/main.go` → `internal/server/server.go` (DI, монтаж маршрутов).

## Frontend (`frontend/`, Angular 21 + ng-zorro + Keycloak)

Standalone-компоненты, состояние на сигналах, стили только через токены. Точка сборки —
`main.ts` → `app.config.ts`. Наружу — nginx `app.gtport.ru` → dev-сервер `:4200` (прокси
`/api` → Go-бэкенд `:8080`).

| `src/environments/*.ts` | Настройки контура (ID модуля, адрес бэкенда, Keycloak); подменяются при сборке. `environment.ts`=база, `.development.ts`=локальная разработка, `.production.ts`=прод, `.uat.ts`=заготовка UAT, `.river.ts`=второй инстанс VPS (свой домен, Keycloak общий с боевым — адрес абсолютный `95850.koara.live`, потому что same-origin на другом домене не сработает). |
| `angular.json` | Конфигурация сборки Angular: входные файлы, стили, режимы production/uat/development/river (последний — второй инстанс VPS, `ng serve --configuration river`). |

| `proxy.river.conf.json` | То же для ВТОРОГО инстанса VPS: `/api` → `localhost:8081` (юнит `dpmodule2-frontend` запускается с ним). Отдельный файл обязателен — с боевым `proxy.conf.json` запрос к `4201/api` ушёл бы в бэкенд первого инстанса, то есть в чужую базу. `/realms` не нужен: фронт `river` ходит в Keycloak абсолютным адресом. |
| `Dockerfile` (frontend) | Сборка фронт-контейнера стенда: `node:24-alpine` собирает бандл (`ARG NG_CONFIG`, дефолт `production` — им же выбирается адрес Keycloak, см. `docs/KEYCLOAK_HANDOVER.md` §5.2), `nginx:alpine` его отдаёт. Порты 8581 (SPA) / 9581 (метрики), healthcheck на `:8581/`. Задаёт `API_BACKEND` (дефолт — адрес хоста стенда), фильтр envsubst и `NGINX_ENTRYPOINT_LOCAL_RESOLVERS` для ленивого DNS. |
| `nginx.conf` (frontend) | ШАБЛОН конфига фронт-контейнера (envsubst подставляет `API_BACKEND` и DNS-серверы). Два сервера: **8581** — раздача SPA с fallback на `index.html`, сквозной `X-Request-Id`, JSON-лог со статусом бэкенда, gzip статики (в образе выключен по умолчанию; `gzip_types` перечислены явно — иначе жался бы только html), вечный кэш хешированных бандлов при некэшируемом `index.html`, прокси `/api` → `$api_backend` **через переменную** (литеральное имя nginx резолвит на старте и падает, когда бэкенда ещё нет) с `client_max_body_size 16m` (умолчания 1 МБ не хватает: отчёт ЛК весит 1,22 МБ) и `^~`, чтобы регулярка статики не перехватывала ручки API; **9581** — метрики для Prometheus (`/metrics` из переменных `stub_status`, сам `/stub_status` под экспортер, остальное 404). |
| `.dockerignore` (frontend) | Что не уезжает в контекст сборки. Главное — `node_modules`: иначе 450+ МБ с машины разработчика ложатся поверх `npm ci`, включая платформозависимые бинарники под чужую систему. |
