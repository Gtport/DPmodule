## Как устроен backend (слои)

Поток данных идёт сверху вниз, зависимости — только «вниз»:

```
handler (HTTP, gin)  →  service (бизнес-логика, RAM-кэши)  →  repository/gorm (БД)
        ↑                          ↑                                   ↑
     port (интерфейсы)      domain (чистые типы)              parser (разбор входных файлов)
```

- **domain** — чистые типы предметной области (вагон, план, справочники), без БД и HTTP.
- **port** — интерфейсы («что умеет хранилище/интеграция»), реализуются в `repository`.
- **service** — вся логика: конвейер обогащения дислокации, приём ЛК, матч плана; держит
  состояние в RAM-кэшах (БД читается на старте, пишется атомарной подменой снимка).
- **repository/gorm** — доступ к PostgreSQL (ORM-модель отделена от доменной).
- **parser** — разбор входных файлов (Excel ЛК, JSON АСУ, Excel план) в доменные типы.
- **handler** — тонкий HTTP-слой (gin), маппинг ошибок в коды; провод в `server.go`.

Точка сборки — `cmd/server/main.go` → `internal/server/server.go` (DI, монтаж маршрутов).

  правило РЖД. `BulkSave` фиксирует активные перед рассылкой в MAX. Экраны — далее.
- `000047_vagon_delay.*.sql` — память о задержках вагонов: `vagon_delay` (эпизод =
  «вагон стоял на станции с… по…», kind 4 — долгий простой / 5 — брошен; эскалация
  4 → 5 затирает kind в том же эпизоде). Ведёт reconcile-слой `applyDelays`; один
  открытый эпизод на вагон (частичный уникальный индекс).
- `000048_vagon_delay_terminal.*.sql` — терминал (`gruzpol_s`) в эпизодах задержек:
  обязателен в «Задержанных вагонах» и фильтре отчёта (решение владельца); бэкфилл
  существующих эпизодов из `vagon_history` по рейсу.
- `000049_pamyatka.*.sql` — вехи памяток ГУ-45 в истории: колонка `pamyatka_state`

  руками Excel-файлом «Журнал движения» — теперь ведёт крон. Раскладка (решение
  владельца 28.07.2026, в модели gtport стояло «уточнить») зафиксирована в
  `COMMENT ON COLUMN`: `nom_gu45_pod`/`date_gu45_pod`/`date_pod`/`place_pod` из

- `000014_plan.*.sql` — таблицы плана подвода (`plan`, `plan_nitka`).
- `000015_plan_history.*.sql` — история загрузок плана (несколько загрузок на станцию,

- `000016_sf.*.sql` / `000017_plan_nitka_is_sf.*.sql` — справочник синонимов с.ф. и флаг с.ф. в нитке.
- `000018_event_journal.*.sql` — единый журнал событий (`disl_update`/`plan_upload`):

- `000035_admin_more_tables.*.sql` — в админ-редактор добавлены sf, naznach_station
  и cargo (строки реестра + русские подписи колонок); служебные created_at/updated_at

- `000032_marka_color_sprav.*.sql` — `marka.color` (цвет отображения вагонов
  атрибуции в UI, hex; перенесён из старого GTport — однозначен внутри группового

## Frontend (`frontend/`, Angular 21 + ng-zorro + Keycloak)

Standalone-компоненты, состояние на сигналах, стили только через токены. Точка сборки —
`main.ts` → `app.config.ts`. Наружу — nginx `app.gtport.ru` → dev-сервер `:4200` (прокси
`/api` → Go-бэкенд `:8080`).
