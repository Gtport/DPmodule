# DPmodule — GTport Universal (активный и единственный проект)

> Точка входа для Claude Code. **Источник правды по процессу — `PROJECT_INSTRUCTIONS.md`**
> в этом каталоге; здесь — только выжимка и навигация. Инфраструктура VPS —
> в `../CLAUDE.md`. При конфликте `.md`: `PROJECT_INSTRUCTIONS.md` → `TARGET.md` → остальные.

## Задача (одна, надолго)
Переписать **GTport** (рабочий инструмент диспетчера логистического центра,
учёт дислокации вагонов) из жёстко заточенного под 3 порта (`АЭ`/`УТ-1`/`ГУТ-2`)
в **универсальный** прототип, настраиваемый под любое предприятие: порт-специфичный
хардкод → в БД, парсеры/структуры — расширяемые.

**Способ — greenfield (зафиксировано):** пишем заново на шаблоне `TMPL_backend`
и переносим бизнес-логику из `gtlogic`. Не доработка старого кода по месту.
- `gtlogic` (= старый GTport) — источник **бизнес-логики и правил** (референс, не трогать).
- `TMPL_backend` — источник **архитектуры** (Ports & Adapters, DI в `main.go`).
- `DPmodule` — то, что пишем (seeded из `TMPL_backend`).

## Два клона (WSL — разработка, VPS — бой) — воркфлоу
Проект ведёт **один человек — владелец**. Клоны разнесены по машинам, синхронизация
только через GitHub (`git@github.com:Gtport/DPmodule.git`):
```
<WSL>/projects/DP/DPmodule          ← разработка: код, тесты, экраны
/home/alex/projects/DPmodule        ← VPS, боевой стенд: только pull + пересборка
```
**Разработка переехала в WSL** (2026-07-25). Разделение ролей:
- **WSL** — пишем код, гоняем `go test`, смотрим экраны на своей копии базы и
  своём Keycloak. Внешние интеграции (АСУ, MAX, памятки, крон «Брошенные») там
  **выключены** — второй инстанс не должен слать формы в живые чаты и дублировать
  забор данных. Конфиг машины разработчика — `config.local.yaml` (вне git,
  шаблон `config.local.example.yaml`), запуск `-config config.local.yaml`.
- **VPS** — обычно только `git pull`, пересборка и рестарт (скил `/deploy`). Боевая
  база, с ней прямо сейчас работает диспетчер, и проверить правку там не на чем:
  своей копии базы нет. Поэтому правим здесь лишь по необходимости — и с тем же
  ритуалом коммита и пуша, что в WSL.
- Копия боевой базы в WSL обновляется `scripts/dev_db_refresh.sh` (дамп снимается
  на VPS по ssh, льётся в локальную базу; боевая только читается). Для разведки
  боевых данных — SSH-туннель ролью `dpport_ro` (только SELECT,
  `scripts/dev_pg_readonly.sql`). Пошагово — **`docs/DEV_WSL.md`**.

Правила (обязательны для владельца И для ассистента):
- **Коммитим прямо в `main`** (соло, решение владельца 2026-07-27). Ветка и PR —
  не обязательный ритуал, а инструмент: заводим ветку, когда работа идёт несколько
  заходов или трогает миграции/конвейер дислокации, то есть когда `main` нужно
  сохранить раскатываемым под возможный хотфикс. Порядок — скил `/commit`.
- **Гейт — `git push`, а не коммит.** `origin/main` — источник деплоя (`/deploy`
  на VPS делает `git pull`). Инвариант: **всё, что ушло в `origin/main`, пригодно
  к раскатке.** Локальные коммиты — свободно; пуш — только когда
  `go build ./...` и `go test ./...` зелёные.
- **Работаем на одной машине за раз** (правки поочерёдные, не параллельные). Машина,
  с которой уходим, **не держит ничего незапушенного** — см. «Начало и конец сессии».
- **Писать код лучше в WSL:** там копия базы, выключенные интеграции и `go test`.
  На VPS правим, когда иначе нельзя (диспетчер стоит, чинить надо сейчас) — и сразу
  после этого коммитим и пушим. Незакоммиченная правка на VPS не пропадает, но
  ведёт себя подло: либо блокирует следующий `pull` («local changes would be
  overwritten»), либо расходится с git молча — `go build` там собирает **из рабочего
  дерева**, и правка уезжает в боевой бинарь невидимо для git.
- **`_reference/seed/` вне git — живёт в каждой папке отдельно.** При обновлении
  справочников синхронизировать вручную (`cp -r`); git их НЕ переносит. Копирование
  мимо git — только для того, что вне git (seed, `config.yaml`, `.env`).
- **Второй `ng serve` на той же машине займёт порт 4200** → конфликт. Dev-сервер
  держим один: на VPS это systemd-юнит `dpmodule-frontend`, в WSL — `npm start`.

## Начало и конец сессии (работа поочерёдно на двух машинах)
Владелец работает то в WSL, то на VPS — **никогда одновременно**. Значит конфликтов
правок по построению нет, а единственный реальный риск — **уйти с машины, не запушив**:
вторая сторона увидит устаревшую картину и примет её за полную.

**Инвариант: машина, с которой ушли, не держит ничего незапушенного.** Тогда git —
полная правда о проекте, и обе стороны это знают.

Начиная сессию (ассистент делает это сам, не дожидаясь просьбы):
```bash
git pull --ff-only
git status -sb          # ждём чисто, без ahead/behind
git log --oneline -5    # чем занимались в прошлый раз и на какой машине
```
Расхождение (`ahead`, грязное дерево, отказ `--ff-only`) — **сказать владельцу сразу**,
до начала работы: скорее всего, на прошлой машине что-то осталось незапушенным.

Заканчивая работу: проверки → коммит → `push` → `git status -sb` чист (порядок — `/commit`).
Работа не доделана — **всё равно коммит**, в ветку `wip/<что>`, и `push`. `git stash`
не использовать: стеш лежит только в своём клоне, в `git status` не виден и забывается.

⚠️ **Контекст разговора через git не ездит.** Ассистент на другой машине увидит только
репозиторий — ни этой переписки, ни принятых в ней решений. Поэтому всё, о чём
договорились, оседает **в том же заходе** в `.md` (раздел «Текущий статус» ниже,
`STRUCTURE.md`, `docs/`) или в сообщение коммита. Не записано — считай, не было.

⚠️ **Что не про конкретную машину — держим внутри `DPmodule/`.** Папка уровнем выше
(`~/projects/DP/`) **не** git-репозиторий: `DP/CLAUDE.md` и `DP/.claude/` — локальные
заметки этой машины, на вторую они не попадут никак.

## Жёсткие правила (нарушать нельзя без явной просьбы)
- **Поведение GTport — эталон.** Новый код даёт те же результаты на тех же входах.
  **Сначала тест (golden), потом перенос.** Перенос — малыми проверяемыми кусками.
- **Никакого нового хардкода** портов. Новые порт-данные → таблицы + `PortRegistry`,
  не `switch`/`map`. Атрибуты порта — через реестр, не `switch port`.
- **GORM-гибрид (канон):** билдер для CRUD и динамических `UPDATE` (только непустые
  поля); сырой SQL дословно через `gorm.Raw().Scan()`/`gorm.Exec()` для аналитики
  (CTE, `DISTINCT ON`, оконные), DDL, атомарной подмены таблиц. ORM-модель отделена
  от доменной. Снапшот-таблицам (`disl_actual`/`disl_new`) — без `gorm.Model`/хуков.
  Схему ведёт `golang-migrate`, **не** `AutoMigrate`.
- **Время — Московское naive, без часовых поясов** (жёсткий инвариант, `TARGET.md`
  §3.11). Всё время (Excel/JSON/БД/API) — Московское без TZ; отдаём как пришло, **не
  корректируем**. Тип `LocalTime` (без `Z`, `2006-01-02T15:04:05`, `timestamp without
  time zone`). «Сейчас» — только по Москве, из **единого** `clock.Now()` (единственное
  место с `LoadLocation("Europe/Moscow")`); штампы `CreatedAt/UpdatedAt` — через него.
  **Запрещено** в коде: `LoadLocation`/`FixedZone`/`.In`/`.UTC()`/сдвиги `Add(±7h/±10h)`.
  Правило «час ≥ 18 → +1 сутки» (`DateNach`/ID) — бизнес-правило, **не** TZ, остаётся.
- **Silo:** один клиент = один экземпляр = одна БД. `enterprise_id` НЕ вводим.
  RAM-движок дислокации (`actualMap` + индексы + обогащение) переносится **как есть**.
- **Падать громко** на целостности данных. Миграции — идемпотентные, только
  добавляющие. Не переписывать модуль целиком без просьбы — минимальное изменение.
- ⚠️ Не путать **«исторические снимки/бэкапы `disl_actual`»** (упраздняем) с
  **бизнес-историей** `vagon_history`/`vagon_operation` (сохраняем).

## Текущий статус
Конфиги и секреты (решение владельца 31.07.2026, переход на Vault + Jenkins):
секрет объявляется **в самом конфиге** шаблоном `${vault:<движок>/<путь>:<ключ>}`,
значение подставляет CI/CD перед стартом — **своего резолвинга Vault в приложении
нет**, поле читается как обычное значение. Покрыты `postgres.password`,
`keycloak.client_secret`, `keycloak.service_account.client_secret`, `max.bot_token`
— всего четыре секрета, больше в хранилище класть нечего. Приоритет: **файл конфига
→ env**; переменные окружения (`PG_PASSWORD`, `KEYCLOAK_CLIENT_SECRET`,
`KEYCLOAK_SA_CLIENT_SECRET`, `MAX_BOT_TOKEN`) остаются **запасным путём** для стендов
без подстановки — боевой VPS (systemd `EnvironmentFile=`) и машина разработчика
продолжают работать без правки юнита. Адаптеры просят секрет по ИМЕНИ ключа через
`port.SecretSource`; сводит два мира `secret.LayeredSource` (конфиг поверх env).
⚠️ **`asu.token` в конфиге НЕТ** (решение владельца 31.07.2026): к провайдеру ходим
через Keycloak, а `X-API-Key` остался лишь запасным режимом для отката и читает ключ
ИЗ ОКРУЖЕНИЯ по имени, которое объявил источник (`data_source.auth_secret_key` для
АСУ, `reference.auth_secret_key` для памяток). Плейсхолдером это и не закрыть:
источников может быть несколько, и заводятся они данными.
Пути Vault: БД — `${vault:kv/databases/postgres/dev:gtport_app}` (боевая конвенция —
один секрет `databases/postgres/dev`, ключ = имя роли БД); остальные в
`config.yaml` пока по образцу шаблона, **согласовать с DevOps**. ⚠️ Конфиг стенда
называется **`config.yaml` и лежит В GIT** (решение владельца 03.08.2026, принято
из ветки тимлида 05.08): его забирает CI/CD под этим именем, прежнее правило
`.gitignore` снято — секретов в файле нет, только плейсхолдеры Vault. Конфиг
боевого VPS переехал в **`config.vps.yaml`** (содержимое не менялось); ⚠️ при
первом деплое этого изменения systemd-юнит `dpmodule-backend` на VPS надо
переключить на `-config config.vps.yaml`, иначе бой прочитает стендовый
`config.yaml` и уйдёт на чужую базу. Файл машины разработчика — `config.local.yaml`
(по-прежнему вне git).

Авторизация у провайдера (решение владельца 31.07.2026): **X-API-Key упраздняется,
ходим через Keycloak** — сервис-аккаунт, поток client_credentials (человека в цикле
нет, поэтому работает и в кронах), токен в `Authorization: Bearer`. Настройки —
`keycloak.service_account` (`token_url`/`client_id`/`client_secret` шаблоном Vault,
env `KEYCLOAK_SA_CLIENT_SECRET` запасным путём); движок — `adapter/oauth`
(кэш токена до истечения с запасом 30 с). Охват — **всё, что ходит к этому
провайдеру**: дислокация АСУ, запрос 601, памятки ГУ-45 (адрес и ключ у них общие).
X-API-Key **оставлен запасным режимом**: `auth_mode` в `data_source.config` для АСУ
и `reference.auth_mode` в конфиге для памяток (`keycloak` | `apikey`). ⚠️ Пустой
`auth_mode` = keycloak, **только если сервис-аккаунт настроен**, иначе apikey — стенд
без заведённого Keycloak (сегодня это бой) не встаёт после обновления кода, а
переключается заполнением блока. Явный `apikey` сильнее — им откатывают один
источник, не трогая прочие.

Конвейер дислокации Stage 1–4 перенесён и в бою: приём ЛК (двухшаговый) и
автозагрузка АСУ-АСУ (крон + ручная), гарды свежести/потерь/«данные не
обновились», единый журнал событий (`disl_update`/`disl_rejected` с кодом гарда/
`plan_upload`/`dict_reload`; кто/чем/когда).

Робот ЛК РЖД — **фоновый запуск** (решение владельца 01.08.2026, после разбора
жалобы «файлы пришли, а в модалке их не видно»). Причина была не во фронте:
забор двух кабинетов занял 53,7 с при `http.write_timeout: 30s`, Go бросил
запись ответа, nginx отдал браузеру 502 («upstream prematurely closed
connection»), обработчик при этом доработал и сложил оба файла — окно молча
осталось со старым списком. Лечить таймаутами не стали: **скоро CI/CD-стенд,
где модули живут в контейнерах за чужим ingress'ом**, и правило «работает без
перестройки прокси» важнее. Поэтому `POST .../robot/run` отвечает 202 сразу,
работа идёт в горутине с контекстом, отвязанным от запроса (claims переносим
руками, иначе журнал теряет актора; потолок — `lk_robot.run_timeout`, дефолт
30m), а модалка опрашивает `GET .../robot/state`. Долгих HTTP-запросов у нас
больше нет — таймауты прокси приложению безразличны. Робот сам делает и шаг 2:
после забора проверяет приём и обновляет дислокацию, не готово — говорит почему.
Прогресс живёт на сервере, поэтому окно можно закрыть и открыть заново, а
повторный запуск на ходу отклоняется (409). Кнопки на главной: **АСУ · ЛК ·
АВТО ЛК** в один ряд карточки «Статус системы» (сокращены, чтобы влезли;
Alt+A/L/R), автозабор — отдельной перемещаемой модалкой, ручная загрузка
осталась своей.

АВТО ЛК — **без Excel** (решение владельца 03.08.2026). Робот больше не качает
xlsx и ничего не кладёт в приём: дислокацию читает прямо из ответа кабинета на
опрос готовности (`GET reports/{id}?minimal=true`) — тем же, чем ЛК рисует
таблицу на экране. Разведка боем: в ответе **136 полей АСОУП** (67 колонок xlsx
были их ОТОБРАЖЕНИЕМ — склейки «наименование (код)»), значения в формате фида
АСУ, метка формирования среза — `data.created_at` (сверена с меткой из шапки
xlsx того же забора: совпала точно). Поэтому парсер новый не писался: переходник
`ParseRows` (`parser/json_rows.go`) перекладывает строку в ту же `jsonVagon` и
идёт через общий `convert`, а поля берутся по тегам рефлексией. Сверка xlsx vs
JSON на одном срезе (4853 вагона обоих кабинетов): вагоны 1:1, 28 из 32 полей
1:1; расхождения — в пользу JSON (секунды в `DATE_OP`, которые Excel срезает;
